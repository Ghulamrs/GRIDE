## Verdict

**No - the document's list is correct almost line by line, but it is not the list of what is left.** It is the list that re-running the 1.25 review finds, and it repeats that review's blind spots: it probes the C++11 additions and the places the review already looked, and it took the library's names from a text search. Walking C++11 clause by clause with 334 new valid programs, 504 new ill-formed ones and a 919-name library census, cpp11 1.30: (1) **miscompiles seven more constructs silently** - a temporary in a mem-initialiser is never destroyed, `d.R::v` through a virtual base reads garbage, `throw e;` and `throw std::move(e)` copy where a move is required, `new T[n]` with an overflowing or negative size allocates or throws the wrong type, `decltype(cs.m)` is `const int`, an enum argument is deduced as `int` and picks the `int` explicit specialisation, `this->a` in a default member initialiser of a class without a constructor reads garbage - and the user-conversion and comment bugs the document names are confirmed; (2) **crashes** (access violation, no message) on two partial specialisations of a variadic class template, and `-O2` does not finish a 3000-term expression in 60 s; (3) **accepts 92 ill-formed programs** that need a diagnostic, among them `static_cast` dropping `const`, assignment through a deleted copy-assignment (a `const` member is overwritten), an ambiguous base conversion (silently the first base), `explicit operator int` used in `s + 1`, every access check on types, destructors and `operator new/delete`, the protected-member rule, abstract and incomplete types in arrays and `throw`, looser exception specifications on overriders, floating and class-type non-type template parameters, redeclarations, `main` rules; (4) **refuses 134 valid programs** of which about half are items the document does not list, many of them C++98: non-type template parameters of pointer, reference, member or `nullptr_t` type, `static_cast` to a base reference, pointers to `const` member functions, `bool b = ptr;`, surrogate calls, conversion function templates, explicit specialisations of class-template members, default arguments accumulating over declarations, a parameter of function type, a local class reading its enclosing class's private members, two `using` declarations merging an overload set, friend templates, a pure virtual destructor, `enable_if` as a non-type default template argument, every `: m{...}`, `volatile` anywhere in a type; and (5) **the library is far thinner than "slightly understated"**: 487 of 919 names from the C++11 synopses of the 25 shipped headers are missing (75 of 88 algorithms, 66 of 89 traits, 34 of 37 `<memory>` names, 17 of 18 in `<exception>`, 85 of 158 iostream names, 44 of 67 in `<cmath>`), and what exists is wrong in places (`std::abs(long)` is `int`, `std::hex` cannot be applied to an `istream`, `substr(pos > size())` does not throw, `istream >> int` on overflow stores garbage and sets nothing, `unique_ptr<T[]>` cannot be constructed, `new int[-1]` throws `bad_alloc`). The document's two architectural judgements stand - two-phase lookup and the Windows exception shapes are the deepest holes - but they are two of six fronts, and the library front is the largest by volume. Section 4 sizes the whole road at about 47 sessions of 1.26's size, of which 17 are library.

## 4. Plan to strict C++11 conformance

"Strictly conforming" means [intro.compliance]: every well-formed program is accepted and executed as the standard says, every ill-formed program that is not NDR gets a diagnostic, all implementation-defined behaviour is documented, and the library is complete for the chosen class of implementation. The phases are in dependency order; effort is in sessions the size of 1.26 (five fixes with their tests, gated against the suite). Every phase keeps the existing gates - the compiler's own 706 cases, the `.error` files, `EXCLUSIONS.md --check` - and adds the ones named.

### 4.0 Decisions "strictly" forces (take them before Phase 1)

1. **Hosted or freestanding, per target.** `__STDC_HOSTED__` is 1 on all four targets today, which claims all 53 + 26 headers everywhere. Recommended: **hosted on x86_64-windows, x86_64-linux, arm64-darwin; freestanding on tms6747** (`__STDC_HOSTED__ 0` there). Freestanding still requires `<ciso646> <cstddef> <cfloat> <limits> <climits> <cstdint> <cstdlib>` (partial: `abort`, `atexit`, `at_quick_exit`, `exit`, `quick_exit`, `_Exit`) `<new> <typeinfo> <exception> <initializer_list> <cstdalign> <cstdarg> <cstdbool> <type_traits> <atomic>` - complete (Table 16, [compliance]/3). Anything beyond on the DSP is a documented extension.
2. **`<thread>` on the C6747.** Not required of a freestanding implementation; `<atomic>` is. On a single-threaded target `<atomic>` is plain loads and stores with compiler barriers, `is_lock_free()` true, fences no-ops; define `__STDCPP_THREADS__` only on the hosted targets once `<thread>` exists ([cpp.predefined]/2 says "if and only if a program can have more than one thread").
3. **Annex B.** Limits are guidelines, but a conforming implementation must not crash: choose and publish minimums (nesting 256, template instantiation depth 1024, 256 initialisers, 1024 parameters, etc.), enforce each with a named message, test each at the limit. The 1.26 stack work already gives most of them.
4. **Dynamic exception specifications.** Deprecated but normative ([except.spec]/9): a violated `throw(T)` must call `std::unexpected()`. cl is not an oracle (MSVC never implemented it); clang/libc++abi on the Itanium targets is; on Windows cpp11 must do the check itself at the throw site or in the frame handler.
5. **`volatile` enters the type system.** Every refusal in row 23 and R3 depends on it; the optimiser must honour it. No conforming implementation can drop a qualifier that changes mangled names and observable behaviour.
6. **Two-phase lookup** stops being "by design". W11 and A15 are conformance failures, not QoI.
7. **Implementation-defined behaviour gets a document** ([intro.compliance]/9 footnote, [intro.defs]): sizes, `long double` width per target, execution character sets, `main`'s signature forms, the locale names (`"C"` only), `__func__` form, etc. Today's `CONFORMANCE.md`/`EXCLUSIONS.md` become that document.
8. **Which C++11 to track.** The 2011 text has defects every real compiler fixes (CWG 1170 access checking in SFINAE, 1402 implicit move, 1579 return by move, 1343/1510...). Recommend: the text as published plus the Core issues clang applies in `-std=c++11` mode, stated in the conformance document; clang `-std=c++11 -pedantic-errors` then stays the oracle.
9. **The banner changes last**, when Phases 1-7 are gated green on every target; until then it stays honest as it is.

### Phase 0 - the measuring instrument (1 session)

- Make the probe sets of this report and the 1.25 review a permanent **conformance suite by clause** inside the compiler's test discipline: `fable\probes\*` (positives with cl's recorded outputs; negatives as `.error` cases), `rev130`'s bundles, the library census (`names.py`) as a test that counts missing names per header, and the cross-target compile (`-arch` x4) of every positive. Freeze today's numbers as the baseline (334 valid: 173/134/18/4; 504 ill-formed: 92 accepted; census 432/487).
- Architecture: none; it is scripts around the existing runner. Gate: the suite reports exactly this report's counts. Risk: low.

### Phase 1 - wrong code and crashes (3 sessions)

W1-W8, W12, A2-A4 and A1. What each needs:
- **W1** mem-initialiser temporaries: the parser lowers each mem-initialiser as a statement; the temporaries of that full-expression need the same end-of-full-expression destruction the body's statements get (1.26 did this for `T&&` and member-of-temporary; this is the third site). **W3** `throw`: `[class.copy]/32` - try the move constructor first for a local operand, always for an xvalue. **W4** `new[]`: compute the byte count with an overflow check and a sign check before the allocation call, throw `bad_array_new_length` (Itanium: `__cxa_throw_bad_array_new_length`; Windows: throw the class). **W5** `decltype(e)` for an unparenthesised member access returns the member's declared type regardless of the object's cv. **W6** deduction: an enum must deduce as itself, not its promoted type; the explicit-specialisation matcher likewise. **W7** NSDMI in a class without a constructor: run the NSDMIs through the same path as the implicit default constructor (the "no object here" path is the one the implicit constructor never takes today). **W2** `d.R::v`: qualified member access through a virtual base must use the vbtable/vbase offset like `R &r = d` does; the garbage says the qualified form takes the static offset. **W8** the partial-specialisation matcher: two specialisations whose patterns differ in how a pack is split; fix the crash first, then the match. **W12**: the optimiser's pass that is quadratic on expression length (forward-values or coalesce over a 3000-term tree) - bound it or make it linear.
- A1-A4 are small checks in the places that already decide the cast, the assignment and the conversion.
- Gates: `e1-isolate`, `e2-isolate2`, `rev130` fo13/ov02/lex12/fo20 go "same"; the 706; cl as oracle. Risks: W1 and W2 touch the expression-lowering and the layout code shared with the Itanium construction-vtable machinery - run the ABI probes (`abi.ps1`) and the three other targets after.

### Phase 2 - the type system's C++98 holes (4 sessions)

R1-R17, R19-R22, R26-R28 and the `volatile` decision. Architecturally:
- **`volatile` as a type qualifier**: a bit on `Type` beside `const`, carried through declarators, typedefs, member functions (`this`), deduction and both manglers (`PVi`/`PECH`, `?g@@3HC`), and a `volatile` flag on `Load`/`Store` in `Ast.h` that every optimiser pass treats as a barrier (no forwarding, no dead-store removal, no coalescing). This is the one change in the phase that crosses from parser into optimiser.
- **Non-type template parameters of pointer/reference/member type** (R1): a template argument that is an address or a member pointer, with its Itanium (`L_Z1fvE`, `L...E`, `Lp`) and MSVC (`$1?gv@@3HA`, `$H?f@@...`) spellings; `nullptr_t` arguments (`LDnE`).
- Pointers to cv member functions (R3): the cv of `this` becomes part of the member-function type and of the mangled name on both ABIs.
- The rest are rules in the overload resolver, the declarator parser and the deduction engine: contextual `bool` from pointers (R4), surrogate calls (R5), conversion function templates (R6: deduce `T` from the target type), explicit specialisations of members (R7), default-argument accumulation (R8), function-type parameters adjusted to pointers (R9), local-class access (R10), `using`-declaration overload merging (R11), friend templates and member alias templates (R12: the parser takes `template <...> friend` and `template <...> using` in a class body as what they are), pure virtual destructor (R13), `{"ab"}` (R14), `M C::*` deduction and `T&&` with array lvalues (R15), unnamed types and constexpr template calls as template arguments (R16), function-template default arguments naming `T` (R17), exception specifications in declarators (R19/R20), `[over.ics.list]` (R21), `auto&` to functions and rvalue references to arrays (R22), `alignas(T)` in a template head (R26), placement `delete` selection (R27), `new T[n]{...}` (R28).
- Gates: `b*`, `c1-temp`, `e1-isolate r*`; mangled names of every new type form compared with cl `/FA` and clang `-S` (`abi.ps1` pattern) on all targets; the 706. Risk: `volatile` through the optimiser is the largest single risk of the plan - every pass must be audited; a measured probe set of volatile accesses (read/write counts in the generated assembly against clang's) is the gate.

### Phase 3 - the preprocessor as translation phases 1-4 (2 sessions)

- Today `Preprocessor` is line-based with macro bodies as strings; W9 (comments in arguments), R29 (`#if` arms), A14 (`#undef` of predefined names, `#define defined`), the `u8`/`L` concatenation check and the pp-number/UCN corners all want a **preprocessing-token** representation: phase 1-2 (UCNs, trigraphs, splices), phase 3 (pp-tokens, comments to one space), phase 4 (directives, macro expansion over token lists with placemarkers and the `defined` rules, `#if` with the full [expr.const] semantics on `intmax_t`/`uintmax_t`), phase 5-6 (string literals, concatenation by prefix rules). The output must keep the line map `Source::Line` so diagnostics and `-g` are unchanged.
- Gates: `a1-lex`, `a2-cpp`, `n1` pp cases; preprocessed output compared with `clang -E -std=c++11` token for token on the suite. Risk: moderate, self-contained; every file passes through it, so the 706 are the regression gate.

### Phase 4 - templates: two-phase lookup and the remaining template holes (8 sessions)

- **Two-phase lookup against token replay.** Token replay cannot bind names at definition time because it never looks at a template body until instantiation. A dependent AST (the textbook answer) is a rewrite of a 26 000-line parser and is not recommended. The workable middle: a **definition-time pass** over every template body that parses it once in a dependent-aware mode - type-dependent expressions and dependent names are typed as "dependent" and skipped semantically, everything else is parsed and looked up for real. Its two outputs: (i) the diagnostics [temp.res]/8-10 require (A15: `nt28`, `nt29`), and (ii) a **binding snapshot**: for every non-dependent name occurrence in the token range, the declaration(s) found at that point, recorded on the token. Replay then binds a snapshotted token to the recorded declaration set (plus, for a dependent call, the ADL candidates found at the point of instantiation), instead of re-looking it up in the instantiation scope. Non-dependent overload sets are thereby fixed at definition (W11, `tp21`); dependent ones still get ADL at instantiation ([temp.dep.candidate]). Cost: one extra parse per template definition; the risk is the dependent-aware parse itself (what is "dependent" in a token stream without types is exactly the set of rules [temp.dep] gives, and the parser already has `Trial`/`SubstitutionFailure` for SFINAE to lean on). 3 sessions.
- **Mangling of dependent expressions** (R25, `tp26`, `tp31`): the Itanium spellings `sr`, `sZ`, `st`, `dt`, `cl` for `sizeof(T)`, qualified names and calls in signatures - "the form that was not measured" - measured against clang on the probe set, and MSVC's `?$...` forms against cl. 1 session.
- The listed holes (4 sessions): explicit instantiation/`extern template` (emit the specialisation's definitions on request; do not emit on `extern`); member templates out of line, member class templates, member alias templates; partly explicit arguments (deduce the rest); `enable_if` in return types and as non-type defaults (R10 of §2, `r03`); packs in base lists, template template packs, lambda capture packs, `alignas` packs, packs beside other arguments and in nested template-ids; function types as template arguments (unblocks `std::function`, `tuple`, `bind`); naming function templates without a call; `M C::*` and `T&&`-array deduction; default template arguments on earlier parameters; the partial-specialisation matcher (W8); explicit constructor templates; `N` from `T[N]`; unnamed types as arguments; `-> decltype(qualified call)`; ADL through template-argument namespaces (R23); explicit specialisation scope rule (R24); dependent `noexcept` comparison (R20).
- Gates: `c1-temp` all same, `rev130\t5`, `p130` templates, `n3` all refused; cl `/permissive-` and clang as oracles; Itanium mangled names of the dependent forms verified by clang `-S` on linux/darwin probes. Risks: the highest in the plan. Snapshot binding can change which overload existing programs call - the 706 and the review bundles are the regression gate; dependent-expression mangling must match clang byte for byte or linux/darwin interop breaks.

### Phase 5 - classes, initialisation, statements, and the diagnostics the standard requires (5 sessions)

- The document's class and expression lists (rows 16-29 of §2) plus W7: `: m{...}` for every member kind, NSDMI braces on arrays and classes, braced default arguments, `new T[n]{...}`, `new T[n][3]`, unrestricted unions with [class.union]/2's deleted members, union member functions, `using Base::f` in a class (overload set composition and access change), block-scope `using` and namespace aliases, deleted destructors and deleted virtuals (a vtable slot naming `__cxa_deleted_virtual` / a trap), `= default` outside the class (user-provided, non-trivial), friend member functions of another class, static member arrays of class type (dynamic initialisation of arrays with their atexit destruction), `operator&&`/`||`/`,`/`->*`, lambdas in constructor initialisers and `[=, &b]`, `::x`, postfix `++` on bit-fields, `const auto &r = {...}`, static references to temporaries and static `initializer_list`s (the backing array gets static storage), class-type `for` conditions, statement attributes, `va_arg` of a struct, constexpr over literals/arrays/addresses/pointer members (the folder learns addresses and arrays as constant values), delegating constructors with virtual bases.
- **The 92 accepted ill-formed programs** (A5-A14): access checking on every named entity (types, enumerators, destructors, `operator new/delete`, the elided copy constructor), the protected rule, friend visibility, abstract/incomplete/void type checks at every use, exception-specification compatibility on overriders and pointer conversions, template parameter and specialisation rules, default-argument rules, constant-expression overflow and shift rules, `main` rules, aggregate rules (no base, no private member in C++11), narrowing in NSDMIs, union rules, redeclaration rules, `alignas` placement, attribute placement, linkage rules.
- Architecture: none new; these are checks at points the parser already passes. Gates: `n1`-`n3` 504 refused; `a*`, `b*` all same; the 706. Risk: medium - each check is local, but there are many, and a wrong check refuses valid code (the positive suite guards that).

### Phase 6 - the Windows exception and class-layout model (5 sessions)

- Row 31-33: `throw;` (`_CxxThrowException(nullptr, nullptr)` from a funclet), a `try` inside a handler (nested funclets: the `__CxxFrameHandler3` state tables allow it - cl's own tables for the same shapes are the measurement), locals with destructors inside handlers (unwind map entries for funclet frames), function-try-blocks on constructors and destructors (the rethrow at the handler's end), `dynamic_cast<T&>` (throwing and catching `std::bad_cast`), **two polymorphic bases and virtual bases with virtual functions** (the Microsoft layout: a vfptr per polymorphic base, `vtordisp` fields, adjustor thunks, the `_RTTIBaseClassArray` with every base's displacement and the MI flag), `thread_local` (SECTIONREL in GRIDE's masm, or the `_tls_index` sequence spelled another way), `volatile` externs (Phase 2 gives the decoration), dynamic exception specifications with `std::unexpected` (decision 4), and `std::terminate` on a `noexcept` violation verified.
- Architecture: the funclet-based EH lowering in `ParserStmt.cpp` (18 `funclet` sites) gains nesting; `ParserVtable.cpp`/layout gains the Microsoft MI model. Gates: `rev130\t6`, `c2-except`, `p130 e17-e21, c04, c05` same on x86_64-windows; `abi.ps1` interop with cl objects both ways for every new shape; the Itanium targets unchanged. Risk: high - these are crash-level failures when wrong, and only cl's emitted tables can be the reference; budget a measuring session per shape.

### Phase 7 - the library (17 sessions)

The hosted claim (decision 1) needs all of Clauses 17-30. Adopting libc++ or libstdc++ is not realistic: both lean on compiler intrinsics (`__is_class`, `__is_enum`, `__is_pod`, `__is_trivially_*`, `__underlying_type`, `__builtin_*`) and on every template feature of Phase 4; writing them for cpp11 is Phase 4 work either way, and the headers would still be a foreign 100 000 lines. Keep writing the project's own library, to the synopses, gated by the census and by behaviour against cl's library (and libc++ via `run.ps1 -ClangRun`).
- **7a (4)** - complete the 25 shipped headers to their C++11 synopses: the 487 census names, with `<type_traits>` first because everything else is written with it; the traits that are not expressible in C++11 (`is_class`, `is_enum`, `is_union`, `is_pod`, `is_standard_layout`, `is_trivial*`, `is_literal_type`, `is_abstract`, `is_polymorphic`, `is_empty`, `underlying_type`, `is_base_of`, `is_constructible` family, `is_nothrow_*`) need **compiler intrinsics** (`__is_enum(T)` etc.) - a small Phase 4 extension. Then `<cmath>`/`<cstdlib>` with the correct overload sets (L1), `<ios>`/`<istream>` manipulators as `ios_base&(ios_base&)` and the missing members (L2, L3), `<string>` (L4, `u16string`, `char_traits`, `to_string` overloads, `rbegin`), `<memory>` (L6 and the rest), `<algorithm>` (75), `<numeric>`, `<limits>`, `<utility>`, `<new>` nothrow forms (and W4's runtime), `<exception>` (L8: `exception_ptr` on Itanium over `__cxa_*`, on Windows over the CRT's `_CxxThrowException`/`__std_exception_*` or an own copy of the thrown object), `<typeinfo>`, `<initializer_list>`, `<array>`, `<vector>`/`<map>`/`<set>` members.
- **7b (4)** - containers and adaptors: `multimap`/`multiset`, `deque`, `list`, `forward_list`, `unordered_map`/`unordered_set` (+ multi), `queue`/`stack`/`priority_queue`, `<iterator>`, `<tuple>`, `<bitset>`, `<functional>` (`function`, `bind`, `mem_fn`, `reference_wrapper`, `hash`; needs Phase 4), `<scoped_allocator>`, allocator-aware constructors throughout.
- **7c (5)** - `<locale>`/`<codecvt>` (a `"C"` locale with every facet), `<regex>`, `<random>`, `<chrono>`/`<ratio>`, `<complex>`, `<valarray>`, `<system_error>`, `<typeindex>`, `<strstream>`, `<streambuf>`, and the 14 C headers (`<cerrno> <cfenv> <cinttypes> <clocale> <csetjmp> <csignal> <cwchar> <cwctype> <cuchar> <ccomplex> <ctgmath> <ciso646> <cstdalign> <cstdbool>`) over each target's C runtime (UCRT, glibc, libSystem, TI RTS).
- **7d (1)** - the freestanding subset exact on tms6747 (Table 16), `__STDC_HOSTED__ 0` there.
- **7e (3)** - `<atomic>` (lock-free on x86-64 and arm64 with the right fences; plain on the C6747), `<thread>`, `<mutex>`, `<condition_variable>`, `<future>` over Win32 and pthreads; `__STDCPP_THREADS__`; `thread_local` on every hosted target (Phase 6 for Windows); thread-safe statics verified under contention on all three.
- Gates: census 919/919 and growing as synopses are added; `d1`-`d7`, `g1` same as cl; a per-header behaviour suite (complexity and iterator-stability assertions for containers, exceptions thrown where [res.on.exception.handling] says); `run.ps1 -ClangRun` as the second oracle where cl's library is itself non-conforming (`num_get` on empty input, dynamic exception specifications). Risks: volume (this is the largest phase); compile time of large headers through token replay (measure `<regex>`, `<random>` early and budget an instantiation cache if replay is quadratic); `<regex>` and `<locale>` are each a session on their own.

### Phase 8 - closure (2 sessions)

- Annex B minimums chosen, enforced by name, tested at the limit (decision 3); the implementation-defined document (decision 7); `EXCLUSIONS.md` reduced to conditionally-supported and implementation-defined items; the conformance suite green on all four targets at `-O0` and `-O2`; then the banner. In the same breath, the QoI the document asks for - report every error, warnings, the instantiation chain - is cheap once Phase 4's definition-time pass exists (it is where the chain comes from).
