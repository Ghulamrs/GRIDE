# Code review: compilation consistency and object sizing (2026-10-08)

Scope: the version 6 pipeline (Pp, CxxParser, Sema, IrGen, X86, Coff, MangleSema), the runtime, the
headers in include/ and the sandbox scripts. Two Opus review agents read the code; every finding listed
as "verified" was checked afterwards against the source or reproduced by compiling a probe with both
cl and cppparse. Findings marked "reported" come from the agents and were not reproduced.

## Verified by experiment

Probe programs: sandbox out\det\arith.cpp (arithmetic), scratch sz.cpp (sizeof/offsets), inc.cpp
(incomplete types). Each was compiled by cl against include/ and by cppparse, linked with the same
runtime, and run.

1. Narrow integer arithmetic is not re-extended. X86.cpp Bin/Un lower 1-, 2- and 4-byte operations in
   64-bit registers and never truncate or re-extend the result; loads do (X86.cpp:411-416, 603-607).
   The 64-bit div/idiv, cqo, shifts and cvtsi2sd then read the garbage in bits 32-63.
   cl: c=858993458 d=1 x=0; cppparse: c=2576980377 d=5 x=4.29497e+09 for c=(0xFFFFFFFFu*3u)/5u,
   d=(0xFFFFFFFFu+2u)%7u, x=(double)(0xFFFFFFFFu+1u). At -O1 even (0xFFFFFFFFu+1u)/2u gives 2147483648
   because SSA keeps the value in a register.
2. Compound assignment is computed in the left operand's type. int e=3; e*=0.5 gives 0 (cl: 1);
   int f=-9; f/=7u gives -1 (cl: 613566755). The fix is the usual arithmetic conversions on both
   operands, then a conversion back to the left type.
3. sizeof of an incomplete class is accepted (SemaExpr.cpp:1149-1150): sizeof(std::stringstream) with
   only the iosfwd declaration gives 8. cl rejects it. sizeof(T&) also returns 8 instead of sizeof(T).
4. The object is written after sema errors. main.cpp:232 enters the compile6 block regardless of
   sema.errorCount(); a unit with undeclared names (error type, size 8) still produces a linkable
   object. The exit code is 1, so scripts that check it are safe; scripts that only test for the
   object are not.
5. Empty base classes are not optimised. struct EB : E { int w; } is 8 bytes with w at 4; cl gives 4
   bytes with w at 0. No class in the compiler or its headers has an empty base today.
6. Output is deterministic: Lexer, IrGen and Sema compiled twice gave byte-identical .obj, .asm and
   IR listings.
7. Every other size and offset in the probe matches cl: all fundamental types, padding and tail
   padding, unions, enums, polymorphic classes, multiple inheritance, string, vector, map, set, the
   exception classes and all stream classes (ios 32, ostream 40, istream 64, __fileostream 48,
   __fileistream 72, ostringstream 64, istringstream 96). The cout/cin spacing seen in the linker
   maps is emission order (cppparse writes cout, cerr, clog, cin), not a size difference.

## Verified in the code

8. No stack probing. The prologue is push rbp / mov rbp,rsp / sub rsp,N followed by stores at the far
   end of the frame (X86.cpp ~700), and __chkstk is never called. Self-built units have frames of up to
   12688 bytes (X86Function::emitInst), main has 8144. Windows commits stack one guard page at a time,
   so a first touch more than a page below the committed region is an access violation. Whether it
   faults depends on how deep the stack was committed before, which makes the crash intermittent.
   Fix: mov eax,N / call __chkstk / sub rsp,rax for frames of 4096 bytes or more.
9. String literal escapes: X86.cpp:848-851 decodes only \n \t \r \0 \\ \" while character literals in
   SemaExpr handle octal, \x and the rest. legacy/Pdf.cpp:70's "\xE2\xE3\xCF\xD3" becomes the letters
   in a self-built binary. Decode once in the front end and pass raw bytes.
10. include/io.h:13 declares _finddata_t.size as unsigned long long. The CRT's _findfirst64i32 uses
    _fsize_t (4 bytes), so name starts at offset 36, not 40; PathUtil.cpp:351 reads the name 4 bytes
    late. This affects the cl-built reference too, only in directory listing.
11. Exception runtime state is process-wide (cppparse_rt.cpp:47-58: g_top, g_inflight, g_caught) while
    the legacy pipeline and -j run worker threads, and every generated function with a destructible
    local pushes a frame. compile6 is single-threaded (copt.threads keeps its default; main.cpp:291 is
    in the legacy path), so this is not the self-host crash, but it is a race for the other paths.
    Fix: __declspec(thread) on the four globals in the cl-built runtime, interlocked static guards.
12. Base pointer conversion (IrGen.cpp:274-288) adds the base offset without a null check and never
    adjusts base-to-derived casts. ios sits at offset 8 inside ostream and istream, so a null
    ostream* converted to ios* becomes 8.
13. A static local of reference type gets the referent's size (IrGen.cpp:1509-1512): static int& r is
    a 4-byte slot and the 8-byte pointer store overwrites the following $guard byte.
14. float globals and static locals are always REAL8 (X86.cpp:807) while loads use movss. The own
    sources use no float.
15. The virtual destructor's vtable slot holds the plain destructor and virtual delete calls it with
    this only, then frees (IrGen.cpp ~900, 1333-1357). MSVC's slot holds the scalar deleting
    destructor ??_G(this, flags). Both compilers emit the vtable as a COMDAT with the same name, so in
    a link that mixes cl and cppparse objects whichever table wins decides between a double free and a
    leak. new[] uses a 16-byte private cookie where MSVC uses 8. Trivial 1/2/4/8-byte classes are
    passed by address and returned through a hidden pointer where MSVC uses registers. Polymorphic
    classes without a user copy constructor are byte-copied including the vptr.
    Consequence: the mix.ps1 bisection (one cppparse object among cl objects) cannot isolate a unit.
    Inline and template functions are SELECT_ANY COMDATs in both, so the first object in link order
    supplies them to everyone. selfhost.ps1 (all-cppparse link) is the only reliable signal.
16. selfhost.ps1:34-37 compares .obj bytes after an ASCII conversion that maps every byte >= 0x80 to
    '?', so opcode or displacement differences in those bytes are reported as identical. Compare the
    raw byte arrays. mix.ps1:26 runs the probe without --obj --msvc-mangling, unlike selfhost.ps1.

## Reported by the agents, not reproduced

17. A throw inside a catch handler skips CatchEnd, so g_caughtCount grows and after 32 entries
    cppparse_catch_begin returns null.
18. Varargs calls do not duplicate float arguments into the integer registers (X86.cpp:395-398).
19. Single-precision lowering: FConst loads the double bit pattern then uses movss; compares use
    ucomisd; fneg flips bit 63; a stack-passed float parameter is homed with movsd.
20. Internal linkage is not modelled: anonymous namespaces are dropped from qualifiedName, static
    locals are PUBLIC with no unit id, file-scope static functions get external decoration, an
    out-of-class inline definition does not mark the symbol inline.
21. Constant pointer tables that cl places in .rdata are dynamically initialised in link order, and
    global destructors are never registered with atexit.
22. A missing include is only a warning, after which undeclared functions are called by bare name.
    _MSC_VER, _MT and _CPPUNWIND are not predefined.
23. sizeOf/alignOf fall back to 8 for a class not yet laid out (Sema.cpp:156, 165); array fields do
    not trigger the element class's layout. Bit-fields are parsed and ignored; anonymous unions and
    structs contribute no size; a polymorphic base that is not first gets a second vptr; virtual
    bases are placed inline without a vbptr.

## Consistent with MSVC (checked)

Fundamental sizes, vptr at offset 0, non-virtual bases in order with no reuse of tail padding, enums,
references as 8 bytes, static members excluded from layout, the Win32 structs in include/windows.h,
_stat64i32 and tm; the calling convention (argument registers, shadow space, 16-byte alignment, r10
for indirect calls, callee-saved registers only in the allocator, constructors returning this); the
272-byte 16-byte-aligned jmp_buf; COFF relocation types and .CRT$XCU flags; per-unit driver state
(fresh objects, setMangleUnitId before registerMetadata); -I order across the scripts.

## Status after the fix pass (same day)

Fixed and covered by test 16 (examples/sample-self): items 1, 2, 8, 9, 10, 11 (runtime state
thread-local), 12, 13, 14, the new[] cookie and polymorphic copies from 15, the selfhost compare and
mix options from 16, and the float constants from 19. Also fixed on the way, outside this list: the
-O3 unroller renamed values defined before the loop, and the legacy type checker recursed on a copy
constructor. Still open: 3 (sizeof on incomplete types, sizeof(T&)), 4 (object written after
errors), 5 (empty base), the vtable slot and small-struct passing from 15, 17, 18, 20, 21, 22, 23.

Found later the same day: a local variable does not hide a function template of the same name in the
parser, so after `<algorithm>` declares `std::count`, `int count = 0; while (count < n + 1)` inside
namespace std is read as a template argument list. The ostream formatting code was renamed to avoid it;
the parser still has the gap. MatrixTest.cpp needs two sema features: member function bodies of a class
template instantiated only when used (Matrix instantiates Vector<Vector<T,C>,R>, whose scalar operators
do not apply to a vector element), and member templates of class templates that see the enclosing
template's parameters (Matrix::trySolve<K>).

## Suggested order of fixes

1. Re-extend narrow arithmetic results and fix compound assignment typing (items 1, 2): they change
   values in hashes and folds, so the self-built compiler cannot produce identical output until done.
2. Stack probing (8) and string escapes (9).
3. Reject sizeof on incomplete types and stop writing objects after errors (3, 4).
4. io.h struct (10), static reference slot (13), base conversion null check (12), thread-local runtime
   state (11).
5. MSVC ABI parity for vtables, array cookies and small structs (15) if mixed links with cl objects are
   ever needed; otherwise document that cppparse objects link only with each other and the C runtime.
