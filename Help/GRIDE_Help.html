C90 · C++11 · Shalimar — Windows · Linux · macOS · TMS6747 — RIDE's conventions

GRIDE 2.0 is a Visual Studio-style IDE for RIDE's toolchain - the C90, C++11 and Shalimar compilers, RIDE's assemblers and linkers, the TMS6747's emulator and simulator - and follows RIDE's conventions: its command lines (from toolchain.json), build rules, error shapes, Compiler Options and debuggers. It holds one project at a time.

1. Quick start: the cppparse example

cppparse is a Visual Studio 2022 C++ solution, built with Visual Studio's cl and link.exe - nothing to set first.

  1. File > Open Project (Ctrl+Shift+O) → examples\cppparse\cppparse.pro. The title shows cppparse [Visual Studio 2022 v143, read-only].
  2. Ctrl+Shift+B builds it (Debug or Release from the toolbar's Config box). The Output pane ends [built …\.gride\out\Release\cppparse.exe].
  3. F5 builds and runs it in the Output pane: cppparse.exe --health . reports on its own sources, then [program returned 0].

The Visual Studio files are only read. cppparse.pro keeps GRIDE's choices for it - compiler cl, the configuration, the arguments - and the build goes to .gride\ beside the .vcxproj.

2. Projects

The .pro file is GRIDE 2.0's own JSON: formatVersion, name, language, target, outputName, sourceFiles (relative to the .pro), includePaths, libraries, activeConfiguration, configurations (defines, flags, link flags, output folder), and when set: toolchain, emulateOnly, programArgs, options (Compiler Options).

Code Composer Studio 7.4 / 5.5 and Visual Studio projects open read only: File > Open Project on a .project, .sln or .vcxproj (or File > Import CCS Project on a folder). Their files are never written; GRIDE's choices for them go to settings.json, or - for a Visual Studio project - to a .pro that names it:

{ "formatVersion": 2, "name": "cppparse", "activeConfiguration": "Release",
  "toolchain": "cl", "programArgs": [ "--health", "." ], "visualStudio": "cppparse.sln" }

3. Building

CommandKey
Build ProjectCtrl+Shift+B
Compile Current FileCtrl+F7
Rebuild Project, Clean Project, Cancel BuildBuild menu
  • Debug or Release from the toolbar's Config box. The project keeps the choice (activeConfiguration).
  • Flags are RIDE's: -g -D_DEBUG=1 / -O2 -DNDEBUG=1 for c90 and cpp11, --debug for shalimar, /Od /Zi /D_DEBUG / /O2 /DNDEBUG for cl. Change them under Project > Compiler Options; only what differs from RIDE's defaults is written to the .pro.
  • A Visual Studio project built with cl also gets its own settings (e.g. /W4 /WX /permissive- /EHsc /MT), without RIDE's header folders in front of Microsoft's.
  • Targets - Windows, Linux, macOS, TMS6747 - from the toolbar's Target box. A target this machine is not builds to assembly only, and says so.
  • Errors go to the Error List; double-click one to reach its line.

5. Debugging

KeyDoesKeyDoes
F8Debug, or carry onF9Breakpoint on / off
F7Step overF6Step into
Ctrl+Up / Ctrl+DownWalk the stackShift+F5Stop
  • Windows: a Debug build carries CodeView and runs under cdb (or lldb where cdb is not installed).
  • TMS6747: sim6747 with the .out, or vm6747 with the assembly.
  • Shalimar: the program debugs itself and stops by statement; Locals says where it is, not what is in it.
  • Panes beside the Output: Locals, Watch, Call Stack, Registers, Memory, Breakpoints.
