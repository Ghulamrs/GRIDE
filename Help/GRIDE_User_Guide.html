1. Start

  1. File > New > Project (Ctrl+Shift+N): pick a language, a template, a name, a location and the targets. GRIDE makes Name\Name.pro with src\, inc\ and lib\, and a workspace Name.grws.
  2. Pick Config (Debug / Release) and Target on the toolbar.
  3. F7 builds; Ctrl+F5 runs the program in the Output pane.

A tool not found? Tools > Toolchain Check shows where each one was looked for; Tools > Options > Toolchains sets the paths.

3. Projects and workspaces

FileHolds
.proOne project: language, targets, folders and files (relative to the .pro), configurations, a compiler per folder, the program's arguments, Compiler Options.
.grwsA workspace: its projects, the startup project, the active Config and Target, breakpoints.
gride.settings.jsonYour IDE settings, in %APPDATA%\GRIDE (or beside GRIDE.exe for a portable copy).
toolchain.jsonEvery tool, library and argument template (section 8).

Opening other IDEs' projects - read only

  • Code Composer Studio 7.4 / 5.5: File > Open > CCS Project, or add one to a workspace. GRIDE reads .project, .cproject and .ccsproject as RIDE does - device, compiler version, each configuration's options, defines, include paths, linker command file, heap, stack, libraries, excluded and linked files - and builds into the project's .gride\ folder. The Output pane notes what is not supported; Project > CCS / VS Mapping shows the mapping.
  • Visual Studio (.sln, .vcxproj, the older .vcproj): File > Open > Project / Workspace. A solution becomes a workspace (projects, dependencies, build order, solution folders); a project brings its filters' files and its Debug / Release (x64, else Win32) defines, include directories, optimisation and libraries. Property sheets, C++/CLI, MFC and build events are noted, not mapped.
  • A project that needs Microsoft's headers builds with Microsoft's cl and link.exe: set Project > Properties > Compiler to cl. cl then also gets the project's own settings (e.g. /W4 /WX /permissive- /EHsc /MT).

The other IDE's files are never written. What GRIDE keeps for such a project - its compiler, a folder's compiler, the program's arguments - goes into the workspace's .grws.

4. Building

Every step is a command template from toolchain.json: source → compile → .asm → assemble → .obj → link → .exe / .out.

ToUse
Build the workspace / the project / one fileF7 / Ctrl+B / Ctrl+F7
Build several Project · Config · Target sets at onceBuild > Batch Build
Set defines, include directories, optimisation, libraries, the linker .cmd fileProject > Properties (Alt+F7), per Config and Target
Set compiler flags (RIDE's table: optimisation, -g, defines, cpp11's --no_compress, shalimar's --debug …)Project > Compiler Options; the command line each compiler gets is shown below the table
Give one folder its own compiler (auto, c90, cpp11, shalimar, cl)Project > Properties
CleanBuild > Clean Workspace / Clean Project
  • Errors (MSVC, TI or GNU format) go to the Error List; double-click one to reach its line.
  • The Output pane shows each part as it starts ($ src (cpp11)), the link, and [built …].
  • Debug compiles with -g -D_DEBUG=1, Release with -O2 -DNDEBUG=1 (cl: /Od /Zi and /O2). The choice is kept in the workspace.
  • A Shalimar program compiles all its .shl files in one go. A target this machine is not builds to assembly only, and says so.
  • When RIDE's own masm / link fail with no fault in your source, GRIDE offers Visual Studio's ml64 and link.exe instead (Tools > Options > General sets whether it asks).

5. Running on the TMS320C6747

A C6747 build assembles with asm6x and links with lnk6x against RTS6x, using the project's .cmd file or RIDE's own. Help > Toolchain Reference > VM6747 / SIM6747 has the details.

7. C ↔ Shalimar

Tools > Convert: Ctrl+Alt+S turns C into Shalimar, Ctrl+Alt+H Shalimar into C. GRIDE can add the result to the project and open it. The converter is c2s; Tools > Options > Converters can name another.

8. Settings and the toolchain file

  • toolchain.json beside GRIDE.exe names every tool, library, argument template and debugger session - GRIDE's code holds none. Your changes go in %APPDATA%\GRIDE\toolchain.json and win field by field; edit them under Tools > Options > Toolchains > Definitions (with Restore shipped defaults). A bad field is reported in the Output pane and in Tools > Toolchain Check, and the shipped value stands. Every field is described in TOOLCHAIN-FORMAT.md.
  • RIDE's settings have a place in gride.settings.json, with RIDE's meaning:
Tools > Options pageRIDE's settings
Projects > RIDE Pathsthe installation's include and lib, the vcvars64.bat whose Visual Studio is used, TI's C6000 compiler and library directories, shared include and library directories, a new project's compiler, the C6747 debugger (auto, sim6747, vm6747)
Projects > Compiler Optionsthe flags a new project starts with
Projects > Defaults and LocationsRIDE's root, CCS projects on or off, the CCS root
Generalthe native-tools question, the indent
