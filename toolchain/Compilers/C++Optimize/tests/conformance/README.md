# cpp11's conformance suite

The measuring instrument for the road to strict ISO/IEC 14882:2011 (Phase 0 of the plan in
`cpp11-1.30-verification.md`, Fable 5.1, 2026-10-28). Every case was judged valid or ill-formed by
clang++ 22.1 `-std=c++11 -pedantic-errors` on cpp11's own headers; every valid case was built and run by cl
14.52 (`/EHsc /O2 /MT /permissive-`), and its output is the expectation.

`cases.tsv` lists every case: `kind` pos or neg; `check` is `output` (the output and exit code must be cl's),
`run` (the exit code only - the output is unspecified, `note` says why) or `own` (cl is the one that is wrong,
`note` says how; cpp11's conforming output is the expectation). A program the oracles found unspecified, or one
whose probe was wrong, is not in the suite at all; neither is an ill-formed program that needs no diagnostic.

## Running it

    powershell -File run-conformance.ps1 [-Cpp11 <cpp11.exe>] [-Filter <regex on set/group/case>] [-Levels -O0,-O2] [-Out <dir>]
    python -I library\census.py [--cpp11 <cpp11.exe>] [--out <dir>]

The default compiler is `GRIDEd\x64\Release\cpp11.exe` of this tree; `masm.exe` and `link.exe` are taken from
beside it, and Microsoft's CRT through vswhere (so Visual Studio must be installed to link). cl and clang are not
needed: their verdicts are recorded. Both scripts print what was fixed (gained) and what regressed (lost) against
the baseline, and exit 1 on a regression. A case that times out is run again alone before its verdict
counts: a program that ends by `std::terminate` can stall in Windows Error Reporting on a busy machine.
Once a release's gate is green, `-Freeze` (and `census.py --freeze`) writes its verdicts as the new baseline.
Nothing goes through cmd.exe.

The 706 cases of cpp11's own `tests\cases` are not here: the tool repository they belonged to is no longer on
this machine.
